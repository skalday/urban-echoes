# 單一動態地圖圖層規劃草稿

本文件用來討論 `map-osm-prototype.html` 的地圖實作方向。核心概念是：地圖只有一個動態顯示層，依據目前選擇的卡牌即時改變畫面，而不是分成植栽 / 交通 / 房價多個手動切換圖層。

## 可用資料範圍

| 資料 | 用途 |
|---|---|
| 綠廊道北段 / 南段線段座標 | 畫出綠廊道主線，並依卡牌改變顏色、連續性與附加圖示 |
| 綠廊道高架橋點位：民族路、林森路 | 第四局交通政策使用，可依卡牌保留、強化或刪除 |
| 立體綠廊範圍：民族路至林森路 | 可作為高架 / 立體綠廊的底色範圍 |
| 綠廊道路口點位 | 第四、五局使用，標示路口截斷、禁止穿越或交通衝突 |
| 車站點位 | 可作為地圖定位輔助，必要時低調顯示 |
| YouTube 站點 | 可作為沿線 emoji / 場景圖示的隨機分布錨點 |
| `材料/行道樹圖資` | 第二、三局植栽牌可使用；若資料太密，先抽樣或隨機生成視覺點 |
| `材料/housing_points.geojson` | 第六局房價政策使用，顯示交易點與建物型態 |
| `材料/housing_heat.js` | 第六局房價政策使用，顯示房價熱區 |

## 地圖共通底稿

| 類型 | 預設顯示方式 | 備註 |
|---|---|---|
| 綠廊道主線 | 綠色粗線，分北段與南段 | 所有卡牌都以這條線為主要視覺對象 |
| 車站 | 小型站點標記 | 預設低調顯示，避免壓過卡牌效果 |
| 路口 | 預設不強調 | 交通相關卡牌才加亮 |
| 高架橋 | 預設不強調 | 第四局交通政策才明顯顯示或移除 |
| 背景色 / 濾鏡 | 依第一局願景改變 | 第一局選擇作為整場地圖的基礎氛圍 |

## 卡牌對應地圖資訊規劃

| 回合 | 卡牌 | 地圖變化 | 顯示元素 | 視覺規則 | 備註 |
|---|---|---|---|---|---|
| 1 都市願景 | 景觀休憩 | 地圖轉為柔和綠色調 | 綠廊道主線、少量休憩 emoji | 背景加淡綠濾鏡；綠廊線維持綠色；沿線隨機放 `🌳`、`🪑`、`🚶` | 第一局主要建立整體氛圍，不需要真實資料點太多 |
| 1 都市願景 | 商業活化 | 地圖轉為暖色調 | 綠廊道主線、商業 emoji | 背景加淡橘 / 暖黃色濾鏡；沿線或車站附近隨機放 `☕`、`🛍️`、`🏪` | 表現商業想像增加，不等於真實店家資料 |
| 1 都市願景 | 交通轉化 | 地圖轉為交通導向 | 綠廊道主線、慢行路線提示 | 綠廊旁加藍色虛線；沿線放 `🚲`、`🚶`、`🚉` | 表現未來慢行路網願景 |
| 1 都市願景 | 大游泳池 L1 | 地圖轉為藍色調 | 綠廊道主線、水池 emoji | 背景加藍色濾鏡；綠廊線變藍；沿線隨機放 `🏊`、`🌊`、`🛟` | 荒謬牌，視覺要明顯偏離綠廊主題 |
| 2 景觀願景 | 空曠廣場 | 綠廊上幾乎沒有樹 | 綠廊道主線、廣場節點 | 綠廊線維持；不顯示或極少顯示樹木；可放少量 `⬜`、`🧱`、`🚶` | 重點是「空」與「開闊」 |
| 2 景觀願景 | 很多高大的樹 | 綠廊種滿高大樹木 | 綠廊道主線、樹木 emoji 或樹點 | 沿綠廊線隨機生成大量 `🌳`；可參考行道樹資料抽樣，但 prototype 可先隨機 | 綠廊本身看起來更密、更綠 |
| 2 景觀願景 | 低矮草和花 | 樹變少，花草增加 | 綠廊道主線、少量樹、花草 emoji | `🌳` 數量少於高大樹牌；增加 `🌼`、`🌷`、`🌱` | 表現低矮、通透、色彩較多 |
| 2 景觀願景 | 大游泳池 L2 | 延續游泳池視覺 | 藍色綠廊、水上活動 emoji | 綠廊線變藍；水上活動 emoji 比 L1 更多或更密 | 第二次選游泳池要看起來更荒謬 |
| 3 景觀維護 | 廣場維護 | 維持簡單、低裝飾 | 廣場 / 維護 emoji | 綠廊線上放少量 `🧹`、`🧱`、`⬜`；樹木與花草較少 | 表現低維護、易管理 |
| 3 景觀維護 | 扁平單一植栽 | 規律重複植栽 | 單一植栽 emoji | 沿線規律排列同一種 `🌱` 或簡單圓點；間距一致 | 視覺要有「單調、可管理」感 |
| 3 景觀維護 | 自然生態圈 | 植栽更自然混雜 | 多種植物 emoji | 沿線不規則混合 `🌳`、`🌿`、`🌼`、`🪲` | 比第二局花草更雜、更有生態感 |
| 3 景觀維護 | 大游泳池維護 L3 | 水池維護負擔增加 | 水上活動 + 維護 emoji | 藍色綠廊；放 `🏊`、`🌊`、`🛟`、`🚧`、`🧹` | 表現荒謬設施帶來維護壓力 |
| 4 交通政策 | 汽機車 | 刪除綠廊高架節點 | 綠廊道主線、路口截斷、高架橋不顯示 | 民族路、林森路高架橋點位移除；路口維持車流穿越感，可放 `🚗`、`🛵` | 表現汽機車優先時，綠廊連續性被交通打斷 |
| 4 交通政策 | 自行車步行優先 | 被路口截斷處強制接回綠廊 | 綠廊道主線、路口、禁止汽機車穿越符號 | 9 個路口加上綠色連接段或封閉標示；放 `🚫🚗`、`🚲`、`🚶` | 表現路口被重新設計成慢行優先 |
| 4 交通政策 | 混合 | 現在的折衷設計 | 綠廊道主線、部分高架、部分路口穿越 | 民族路、林森路高架橋保留；部分路口仍被車道穿越；同時顯示 `🚗`、`🚲`、`🚶` | 表現有些地方立體化迴避車道，有些保持路口穿越 |
| 4 交通政策 | 電動平衡車 L4 | 增加大量平衡車符號 | 綠廊道主線、平衡車 emoji | 沿線大量放 `🛴`，可用歪斜虛線表示路線不穩定 | 荒謬牌，符號密度可刻意過量 |
| 5 交通設計 | 減速街廓 | 標出可能衝突路口 | 路口、爆炸 emoji、減速提示 | 在部分路口放 `💥`、`⚠️`、`🛑`；衝突感中等 | 爆炸 emoji 用來指出交通衝突可能發生處 |
| 5 交通設計 | 嚴格徒步限制 | 衝突集中在車流被阻擋處 | 路口、爆炸 emoji、禁止車輛符號 | 部分路段加行人專用色塊；車流端點放 `💥`、`🚫🚗` | 表現車輛被限制後的衝突 |
| 5 交通設計 | 人車分流 | 衝突點減少但工程感增加 | 路口、分隔線、少量爆炸 emoji | 綠廊旁畫分隔線；只在大型路口放少量 `💥` 或 `⚠️` | 表現分流降低衝突，但仍有節點需要處理 |
| 5 交通設計 | 電動平衡車專用道 L5 | 平衡車衝突增加 | 平衡車 emoji、爆炸 emoji | `🛴` 與 `💥` 沿線密集出現，尤其路口與行人節點 | 荒謬牌，衝突感可以最強 |
| 6 房價政策 | 市場自然發展 | 顯示房價資料但不強化趨勢 | 房價熱區、建物型態 emoji / 點位 | 載入 `housing_heat.js` 低透明度；`housing_points.geojson` 抽樣顯示建物型態 | 建物增加 / 減少符號保持中性 |
| 6 房價政策 | 居住正義保障 | 顯示房價壓力被抑制 | 房價熱區、住宅保護符號、建物減少 / 穩定符號 | 熱區透明度降低；住宅類點位旁放 `🛡️`、`🏠↘` 或 `🏠＝` | 表現政策讓居住壓力變穩定 |
| 6 房價政策 | 招商開發優先 | 顯示房價與開發升溫 | 房價熱區、高價交易點、建物增加符號 | 熱區加強橘紅色；高 percentile 點位旁放 `🏢↗`、`🏗️` | 表現開發與房價壓力增加 |
| 6 房價政策 | 賽博龐克大樓 L6 | 誇張未來建物出現 | 房價熱區、巨大建物 emoji | 熱區高飽和；沿線或車站附近放大型 `🏙️`、`🏢`、`✨` | 荒謬牌，比例可以刻意不合理 |

## 單一動態圖層實作原則

| 原則 | 說明 |
|---|---|
| 不保留圖層切換按鈕 | prototype 改成選卡牌或 hover 卡牌時呼叫地圖重繪 |
| 永遠先清空動態元素 | 每次切換卡牌時清掉 emoji、臨時線段、熱區、爆炸點，再畫新狀態 |
| 綠廊主線永遠是核心 | 第一至五局主要改變綠廊線段顏色、連續性、附加 emoji 和路口處理 |
| 第六局才載入房價資料 | 避免前五局被房價點位干擾 |
| emoji 是 prototype 視覺語言 | 先用 emoji 快速測試辨識度，之後再決定是否換成正式 icon |
| 隨機點位要可重現 | 若沿綠廊隨機撒樹、花、emoji，建議用固定 seed 或預先生成座標，避免每次刷新都不同 |

## 建議資料結構

每張牌對應一個 `mapSceneId`，地圖只根據該 id 重繪。

```js
const cardMapScenes = {
  "vision-pool": {
    title: "大游泳池",
    backgroundTint: "blue",
    corridorStyle: "blue",
    emojiAlongCorridor: ["🏊", "🌊", "🛟"],
    density: "medium",
    showHousing: false,
    showIntersections: false,
    showBridgeNodes: false
  },
  "traffic-bike-walk": {
    title: "自行車步行優先",
    backgroundTint: "green",
    corridorStyle: "connected-green",
    emojiAlongCorridor: ["🚲", "🚶"],
    showIntersections: true,
    intersectionTreatment: "ban-cars",
    showBridgeNodes: true
  }
};
```

prototype 中可先做：

```js
renderPolicyMapScene(card.mapSceneId);
```

## 待確認問題

| 問題 | 建議預設 |
|---|---|
| 地圖是 hover 卡牌時預覽，還是 click 選定後才變化？ | prototype 先做 hover 預覽 + click 固定 |
| emoji 是否可以作為 prototype 的主要視覺元素？ | 可以，正式版再換 icon |
| 樹木 / 花草要用真實行道樹資料還是隨機撒點？ | prototype 先沿綠廊隨機撒點，後續再接行道樹抽樣 |
| 第五局爆炸 emoji 是否每張交通設計牌都要有？ | 是，但數量與位置依卡牌不同 |
| 第六局建物增加 / 減少要顯示哪些型態？ | 先用 `housing_points.geojson` 的 `type` 欄位分成透天厝、住宅大樓、華廈、公寓 |
